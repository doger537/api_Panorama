# TTKMap: правила разработки

MVP определяют specification.md и docs/reference_raw.md. Offline, этажи, аналитика, AI-распознавание, несколько зданий и реконструкция 3D — backlog.

Перед изменением прочитайте CONTRACTS/AGENTS.md и TASKS/WORKPLAN.md. TASKS/manifest.json — источник задач; WORKPLAN генерируется командой `python scripts/render_workplan.py`. Исторический статус не является доказательством работоспособности. Завершение отмечается после merge.

Работайте в короткой ветке на связный результат, не на main. При конкурентной работе используйте разные worktrees; не переключайте чужой checkout и не перезаписывайте чужие изменения. Перед новой задачей проверьте git status и актуальность origin/main. Не используйте reset --hard, checkout -- или force-push для ремонта общей работы.

Задача может включать необходимые shared-код, wiring, контракт и проверки. allowed_paths помогают определить владельца review, а не запрещают согласованное исправление интеграции. Несовместимые API/DB-изменения требуют согласованного обновления потребителей и миграции. Не создавайте альтернативную реализацию ради границ файлов.

PR описывает результат, проверки и ограничения. Независимое review необходимо для auth, данных, контрактов и worker. Для простой документации достаточно проверки diff. Публикация, push, PR, сообщения команде и VibeTeamOS Hub — только при авторизации пользователя. Локальные изменения и проверки не требуют повторного согласования.

Backend: FastAPI/Python 3.12/SQLite. FK, WAL, busy timeout обязательны. Init schema только для пустой БД; существующие данные не удалять ради тестов. Frontend: React/TypeScript/Vite, общие DTO из CONTRACTS/types.ts. Worker Hugin работает отдельно от HTTP.

Функция готова, когда её реальный путь подключён и проверен. Mock-only тест не закрывает браузерную интеграцию или stitching. Ошибка никогда не представляется успехом. Проверки запускайте отдельно из корня:

- `docker compose --profile test build backend-test`
- `docker compose --profile test run --rm backend-test python -m pytest backend/tests -q`
- `npm --prefix frontend run test`
- `npm --prefix frontend run build`
- `npm --prefix frontend run test:e2e`
- `git diff --check`

Тяжёлые тесты нужны при изменении соответствующего поведения и перед релизом, а не для любого изменения текста. Камера на телефоне требует HTTPS. Реальная device acceptance записывается с устройствами и измерениями; не выдавайте эмуляцию за испытание телефона.
